# Tool Keeper

**AI 每回答一次，都要把手上所有工具的说明书重读一遍——包括你从来用不到的哪些。读得越多，它挑得越不准。这个插件让你把用不到的收起来，把留下的说明书改成你自己的话。**

---

## 它解决什么问题

AI 能搜网页、读文件，是因为手边放着一批「工具」，每个工具都带一份说明书，告诉 AI 它是什么、什么时候用、参数怎么填。AI 没有记忆，每轮都要把全部说明书重读一遍。

麻烦有三处：

- **装一个服务带来十几个工具，常用的只有两三个**，说明书照样每轮参与争夺它的注意力。
- **服务器还附带一整页「说明页」**（系统提示词里的使用说明段落），同样每轮被读。
- **说明书是厂商写的，你改不了**，里面常有大段「你必须先调用我」这类命令句。

工具一多、名字又像，AI 还容易挑错。

最关键的是**说明与实际能力对不上**：你关掉了 40 个工具里的 38 个，只剩 2 个能用，但那页说明还在讲另外 38 个——AI 会照着它去找一个已经不在的工具。

这个插件做两件事：**把用不上的工具真收起来**（不是界面隐藏，是从发给 AI 的清单里消失）；**把说明书改成你自己的话**。关掉一台服务器时，它的工具与说明页**一起消失**，开回来一起恢复。

---

## 它是怎么工作的

一个 MCP 服务器连上后，DSH 拿到它提供的工具清单，把每个工具「上架」——登记进 AI 能看见的注册表。模型看到的说明书，就是上架那一刻存进去的内容。

这个插件守在两处，各自做一件事：

| 时机 | 管什么 | 写在哪 |
|---|---|---|
| 上架那一刻（注册期） | 这个工具**上不上架**、说明书换成什么 | `index.js` |
| 组装系统提示词时 | 这台服务器的**说明页**要不要出现、换成什么 | `instructions.js` |

因为判定发生在这两个时刻，所以**改完配置要重启 DSH 才生效**。设置页顶部会常驻提示「已保存，重启后生效」。

---

## 装上之后

**什么都不做也是对的。出厂状态不管任何工具**——工具数量、说明书内容，跟没装完全一样。关哪个、改哪句，由你决定。

先跟 AI 说「**列出所有工具**」，它会按来源分组报给你。

## 两种用法

### 一、直接说话

AI 会调插件自带的 `tool_keeper` 工具：

| 你说 | 会发生什么 |
|---|---|
| 列出所有工具 | 按来源分组列出，受保护的会标出来 |
| 把 lexiang 整个关掉 | `lexiang` 的工具与说明页一起消失；开回来之后你的配置原样生效 |
| 关掉 create_dataset | 只关这一个工具 |
| 把 exa 打开了 | 整台重新上架，你之前关掉的工具仍然关着 |
| context7 那个说明太啰嗦了，改成「把包名解析成库 ID」 | 改这个**工具**的说明 |
| 把 context7 整页说明换成一句「查库文档用 context7」 | 改这台**服务器**的说明页 |
| 恢复某个工具的原始说明 | 撤销该工具的改写 |
| 恢复出厂 | 清空所有规则 |

### 二、点界面

打开 **设置 → 工具管理**：

| 位置 | 有什么 |
|---|---|
| 工具栏 | 搜索框、展开/折叠、刷新、导出、导入 |
| 摘要 | 当前屏幕上有多少个工具、隐藏了多少 |
| 分组 | 内置工具、MCP · 各服务器；每个来源一张卡片，默认折叠，点标题行展开 |
| MCP 卡片最右 | **服务器开关**（关掉整台）+ **编辑**（改写这台服务器的说明页） |
| 每一行 | 图标、工具名、右边的开关 |
| 点工具名 | 展开编辑区：左边厂商原文，右边你的改写 |
| 底部 | 恢复出厂 |

细节：

- **两个编辑入口别搞混**：点**工具名**改的是单个工具的说明；点 MCP 卡片最右的**编辑**改的是这台服务器的整页说明。后者再点一次或按 Esc 收起。
- **服务器说明页是整段替换**：左边显示厂商原文（含 `### MCP server: 名字` 这一行标题），右边写你的版本——那行标题也是正文的一部分，想保留就自己写回去。留空 = 原样。服务器停用时也能先写好，启用后生效。
- **导出**把配置下载成 `tool-keeper-config-<时间戳>.json`，导出的是磁盘上的当前配置。
- **导入**整份替换配置，导入前自动备份成 `tool-keeper.json.bak-<时间戳>`，成功后告诉你备份文件名；内容有问题会被拒绝。文件不要超过 256KB。
- **标「受保护」的工具没有开关**。画一个点不动的开关是骗人。
- **开关显示的状态是真的**：被规则关掉的工具就显示关闭。

## 规则怎么生效

### 三个入口，同一份配置

| 入口 | 写什么 |
|---|---|
| 服务器开关（每台 MCP） | `servers.<名>.enabled` |
| 服务器说明页改写（MCP 卡片最右「编辑」） | `servers.<名>.rewrite` |
| 单工具开关（每行右边） | `tools.<完整名>` = `drop` / `keep` |

`servers.<名>` 的两个字段互不影响：`enabled: false` 让工具与说明页一起消失；`rewrite` 只换说明页，不碰工具。

**插件级启停不在这里**：那归 DSH 的插件页。在插件页停用插件 = 本插件不执行，工具全部原样。

**没写规则的工具默认可见。** 新装的服务、新出现的工具，先露出来让你看见，再由你决定关不关。

### 冲突时听谁的

```
受保护  >  服务器开关  >  单工具规则
```

服务器开关是物理闸：整台关掉就是一个不剩，单工具写 `keep` 也救不回来；开回来之后，单工具规则原样生效。

工具改写与说明页改写各自独立，都和开关正交：没被藏起来的工具/服务器，你写的改写一直生效。

### 有几个工具关不掉

```
read  write  edit  glob  grep  pwsh
present  todo_write  ask_user_question  tool_keeper  skill
```

硬写进配置不会生效，而且会告诉你怎么回事——不会静默忽略。

### 边界（如实说）

完整提示词类预设下，宿主会在最后恢复完整人设，说明页的过滤与改写都被覆盖；插件检测不到这种预设（宿主没给标志），但会在诊断里如实报「本次未生效」，界面不会冒充「已隐藏」。停用服务器的资源仍可被显式点名读取。两条都已记入 [docs/KNOWN-ISSUES.md](./docs/KNOWN-ISSUES.md)（七、八）。

## 也可以直接改文件

配置在 `~/.dsh/tool-keeper.json`，第一次运行自动生成一份空的。

```jsonc
{
  "servers": {
    // 整台临时关掉（开回来之后，逐条规则原样生效）
    "lexiang": { "enabled": false },

    // 改写这台服务器的说明页（空 = 原样；整段替换，含标题行）
    "context7": { "rewrite": "### MCP server: context7\n\n用 context7 查库的最新文档。" }
  },

  "tools": {
    // 关掉一个工具；受保护的工具写了会被拒绝并说明原因
    "mcp__exa__agent_run": "drop"
  },

  "rewrite": {
    // 只改工具说明
    "mcp__tinyfish__search": "搜索网页与外部知识。",

    // 同时改工具说明和参数说明
    "mcp__tinyfish__fetch_content": {
      "description": "读取网页正文，支持一次 10 个 URL。",
      "properties": {
        "include_selectors": "CSS 选择器，只提取匹配的元素。"
      }
    }
  }
}
```

**只有开 / 关一种选择**：没写的默认开，写 `"drop"` 的关。配置里出现大量 `"drop"` 是正常的——关一个工具就是一条。

## 只改文字，不碰结构

工具定义里除了说明，还有参数类型、哪些必填、可选值、默认值——这些决定怎么调用。**插件一个都不动。**

结构改错 → 工具直接报错，功能彻底坏；文字改错 → 最多说明写得不准，工具照样能用。只做低风险的那一半。

---

## 出问题不会把你锁死

| 情况 | 结果 |
|---|---|
| 配置文件写坏了 | 照常启动，全部工具放行，日志报错 |
| 插件自己出 bug | 那个工具原样放行，不卡住别的工具注册 |
| 补丁装不上 | 页面红条明说「没装上」，不假装在工作 |
| 说明页处理出错 | 系统提示词原样放行，只记一条诊断 |
| 卸载插件或在 DSH 插件页停用 | 一切回到服务器原样 |
