# 独立审计：发现与处理

一次对抗性审计（审计员不知道我的判断，只读源码 + 自跑测试 + 在**副本**上做变异 + 独立差分台）。
它的价值在于**推翻了我自己的结论**，而不是复述我的文档。

审计原则：不信项目文档里的自我评价，只信跑出来的结果。

---

## 审计怎么做的

- 只读源码 + 自己跑 138 条测试
- 在项目副本上做 **27 个变异**，还原后复核
- 建了一个**差分台**：真 `apply()` 装补丁 → 走被包装的 `register` → 再调真 API handler，
  对比「引擎实际行为」与「页面拿到的状态」
- 对运行实例做只读探测

**结果：15 捕获 / 12 未捕获。** 未捕获里 `index.js` 5/5 全漏、`Section` 逻辑 3/3 全漏——
页面行为测试只覆盖了纯展示组件，恰好漏掉所有会写数据、会读运行期状态的部分。

审计员自曝了一件事：它做同源校验探测时发的一个 `op=set` 被接受了
（`tools:{"__proto__":"drop"}`），真实写进了配置；随后还原并逐字节比对确认一致。
这份自曝本身就是要报的东西——见下文 H6。

## 未修（明确记录，不含糊过去）

| 编号 | 问题 | 为什么不修 |
|---|---|---|
| **H3** | `readKnownServers` 的手写正则只认一种 YAML 写法。审计实测：引号包裹、服务器名带点、4 空格缩进、行尾注释、流式对象**五种全部失效**。失效时该服务器的规则静默不生效，而 `computeDiagnostics` 还会给每个已配置服务器报「server not found」硬错误 | 要修就得引入 YAML 解析或改数据源（读 mcp-manager 的 Config）。这是**独立一块工作**，混在这次里会让改动面失控。已列为下一步第一优先 |

## 审计确认成立的部分（不必再动）

审计对宿主半失败路径的评价是「做得比文档承诺还好」：7 种坏输入全部未抛、全部 fail-open，
原因可见（服务缺失 / `register` 非函数 / 冻结 / 只读 getter / `ctx.get` 抛异常 / 半截 JSON / 配置不存在）。

其余确认项：单次 apply 的 restore 干净；16 个 `--dsw-*` 主题 token 全部存在于 `app.asar`
（包括看着像笔误的 `--ds-font-family-code`，而 `--dsw-font-family-code` 反而不存在）；
出厂基线全空、保护名单、优先级链、原子写、`ctx.inject(['webServer'])` 的写法都成立。

## 审计没验成的事（UNVERIFIABLE，不冒充通过）

1. **浏览器半在真实页面里的样子**。客户端 Slot 探测超时（当时没有页面应答），审计员没有亲眼看到导航里出现「工具守卫」，也无法核对 token 的定义值。宿主侧只确认了 `toolwarden` 工具已注册且 schema 一致。
2. **真实重启后的行为**。H2/H5 的证据来自「真 `apply()` + 真 handler 的离线复现」，不是真机重启。
3. **改写后的 definition 是否被下游重新校验**（与 VERIFICATION-P4 同级）。
4. **DSH 升级后的契约保鲜**——对照只基于本机 0.2.2-rc.2 与几个现行插件，不是上游权威文档。

## 这次审计教给我的

我自己的 UI 审计（[UI-AUDIT.md](./UI-AUDIT.md)）找出了「页面显示假状态」，
但**没发现我自己引入的开关 bug**——我把显示改成读 `effective`，却忘了写回路径还读 `tools`。
同一处代码，改了一半。

而我的测试恰好只覆盖展示组件，所以那个 bug 全绿通过。

结论：**改一处状态来源，必须同时检查所有读写它的地方**；
**只测纯展示组件的测试，证明不了页面能用**。
