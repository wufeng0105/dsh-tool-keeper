# 为什么这样实现

改机制之前先读这个文件。它记录当前设计的依据，以及必须遵守的约束。

用法见 [README](../README.md)。

---

## 一、要解决的问题与核心机制

MCP 服务器默认给十几个工具，常用的只有两三个；工具说明是厂商写的，常带「你必须先调用我」这类指令，改不了。

插件要拿到两样东西：**能挑**（用不上的不发给模型）、**能改**（说明文字由用户决定）。省 token 是副产品——如果只为省 token，`restrict()` 就够了，不必拦截注册入口。

### 为什么改写必须发生在注册期

模型看到的工具说明从哪里来？三条证据（源码，L3）：

- MCP 工具与内置工具走同一个注册入口 `ctx.tools.register(definition)`（`dsh-mcp-client/src/tools.ts`）。
- `description` 在构造 definition 时写入，不是每次读取时取（`dsh-mcp-client/src/tools.ts` 的 `createMcpToolDefinition`）。
- 模型看到的 schema 由 `projectToolSchema()` 从注册的 definition 投影（`dsh-tools/src/schema.ts`）。

所以模型能看到的文字 = 注册那一刻存进 definition 的字段。`restrict()` 只改变「哪些 definition 可见」，不改字段内容。**改写只能发生在注册期。**

这也决定了验收方法：`Tool.listTools` 返回的 `description` 就是模型看到的那份。

### 为什么不走另外两条路

- **`restrict()` 管准入 + 另一个机制管改写**：另一个机制照样要在注册期改 definition，一件事做两遍，两套状态还要同步。
- **等模型来读的时候再改**：读取发生在 `dsh-tools` 包内部，拦截它要改宿主代码；且每个请求都要改一遍，成本远高于注册期一次。

### 一个必须满足的时序约束

判定必须在**每个工具自己的注册调用里**发生，不能「插件加载时算一次黑名单」。MCP 服务器是异步连接的：插件先加载时工具清单还是空的，算出来就是空名单，没有重试就会冷启动失效——而冷启动是最常见的启动方式。

### 说明页半边为什么也归服务器开关

一台 MCP 服务器在系统提示词里占两处：它的**说明段**（`mcp:<server>`）和**名单段**里它的名字（`mcp-resource-servers`）。关掉服务器只藏工具、却留着整页说明，模型每轮照样读一遍——这正是本插件要消除的浪费，只做一半等于没做。

**为什么不做第二个开关**：「服务器开 / 说明页关」这类组合没有正当用途，两个开关只是把「看起来在工作、实际浪费上下文」的 bug 态制度化。一个开关管两半：关 = 工具、说明页、名单名字一起消失；开 = 一起回来。

**为什么代码分成两半**：工具半边在注册期（`index.js` 的注册补丁），说明页半边在组装期（`instructions.js` 的 `system-prompt/assemble` waterfall）。两个时机、两套失败模式，硬塞进一个文件只会让 fail-open 逻辑互相纠缠。两条都读同一份启动时规则 `servers.<名>.enabled`，重启才生效——与工具半边完全一致，用户只需要记一个心智模型。

**为什么界面只在有运行时事实时才说「已隐藏」**：`removed` 是最近一次组装真的滤掉了什么。配置说了算、运行时说了不算的两处（未连接、完整提示词预设），如果说成「已隐藏」就是在冒充。

## 二、只改文字，不碰结构

改的只有两处：工具的 `description`，和参数里的 `properties.<名字>.description`。

**不碰**：`type`、`required`、`enum`、有哪些参数、默认值。

风险不对等：结构改错 → 工具直接报错，功能彻底坏；文字改错 → 最多说明不准，工具照样能用。只做低风险的一半。

### 规则冲突时听谁的

服务器开关是「整台取消注册」的物理闸，压过一切逐条规则，否则「关 = 一个不剩」就是空话。最具体者胜只在逐条规则之间成立：

```
受保护  >  服务器开关  >  单工具规则
```

`rules.js` 的 `decide()` 是这条链的唯一实现，设置页显示的开关状态取它的结果（`effective`），不由页面另行推断。界面开关因此是二态（开/关），不是三态。

两条边界：

- **判定不猜宿主**。工具归属哪台服务器只从工具名 `mcp__<server>__<leaf>` 解析；不读宿主配置、不问「现在有哪些服务器」。用户显式写下的规则就是意图；服务器没连上时没有工具出现，规则自然惰性。
- **单工具规则是唯一的选择层**。没明确 `drop` 的默认 `keep`；新工具默认可见。服务器名写错或服务器被移除时，判定不了「改名」还是「没连上」，统一降为诊断警告，规则保留，连上后自动恢复。

### 插件级启停不在本插件

停用整个插件是 DSH 插件页的职责。本插件不维护 `enabled` 之类的全局开关：关掉插件 = 本文件根本不执行，工具全部原样，不需要第二道总闸。

## 三、配置为什么单独放一个文件

配置在 `~/.dsh/tool-keeper.json`，不写进 profile 的 `cordis.patch.yml`。

界面会频繁写这个文件，而 `cordis.patch.yml` 是用户的主配置，混着别人的行和注释，程序化改写它有冲掉用户内容的风险。分开写，坏了也只坏自己这一个文件。

读写集中在 `config.js`：读解析、写前校验、原子写、备份各只有一份，宿主半、设置页 API、模型工具三条入口共用。

---

## 四、界面为什么是设置页里的一页

注册一个 `settings.section` 槽位（`{id, order?, label?}`）就够。不走侧边栏面板，因为那要与 `sidebar.panellist` 和 `main` 联动、协调 dispatch，复杂度不成比例。

### 一个必须记住的坑

挂 HTTP 接口用 `ctx.inject(['webServer'], cb)` 这种**运行期注入**，**不能把 `webServer` 写进 `inject` 数组**。headless 环境下没有这个服务，写进 `inject` 会让插件永远 pending，宿主判定 web 启动失败。

### 界面必须与引擎一致

- 页面数字必须等于模型实际所见，不能让「界面说藏了 N 个、实际一个没藏」。
- 写回必须保留未提交的字段：`state.rules.servers` 返回完整条目，否则界面整块提交会抹掉别的服务器配置。
- 控件不撒谎：整台服务器停用时该行开关置灰；其余情况下点了就真写（重启后生效）。

## 五、为什么还要给模型一个工具

`tool_keeper`。设置页给人用，这个工具给模型用，两者写同一份配置、走同一套判定。为了关掉一个工具去点界面不值得，说一句话就行。

`server` 动作只接受 `enabled: true/false`——只控制整台上不上架，不碰单工具选择。

## 六、可靠性与已知风险

五条约束，代码里所有「绝不阻断注册」「失败要可见」的注释都指到这里：

1. **冷启动即生效** —— 补丁在 `apply` 期间安装，早于任何 MCP 连接。
2. **绝不中断注册链** —— 本插件自身的错误必须被吞掉并记为诊断，不能让工具因插件的 bug 注册失败。说明页半边同理：waterfall 监听器内部出错时原样放行上游结果，不弄坏系统提示词。
3. **失败必须可见** —— 补丁装不上时报 `patched: false` 并在界面告警；说明页监听器装不上时报「说明页过滤未安装」诊断。
4. **配置损坏不锁死** —— 解析失败按全放行运行。
5. **管理入口始终可用** —— 模型工具与设置页 API 不受过滤影响，用户随时能改回来。

### 已知风险与退路

| 风险 | 症状 | 怎么发现 | 退路 |
|---|---|---|---|
| 宿主改了 `register` 的签名 | 加载抛错，或静默不生效 | 启动时断言 `typeof register === 'function'`；装完查工具数 | 退回 `restrict()`，只隐藏不改写 |
| 服务被冻结（frozen/sealed） | `Reflect.set` 抛错 | 捕获后置 `patched: false` 并在界面告警 | 同上 |
| 内部调用绕过替换（直接 `this.register`） | 改写不生效但无报错 | 装完查 `Tool.listTools` 里的 description | 同上 |
| Cordis 代理让覆写失效 | 同上 | 同上 | 同上 |
| 宿主改了说明段名字或名单段文案 | 说明页半边静默失效 | 诊断「本次组装未见其说明段」/「名单段格式与预期不符」；界面不显示「已隐藏」 | fail-open：说明页原样，工具半边不受影响 |
| 完整提示词预设会话 | 说明页过滤被宿主恢复覆盖 | 本插件检测不到（宿主不给标志） | 如实诊断并写入 KNOWN-ISSUES，不冒充 |

**统一兜底**：在 DSH 插件页停用插件，或在宿主里卸载——插件代码不再执行，工具全部原样。
