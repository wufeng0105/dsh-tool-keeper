# UI 审计记录

按 `ytcw`（一体成文）的纪律做的一次前端审计。这套纪律的核心不是「把每块做好」，
而是 **累积状态**：逐段检查看不见的病，合起来读才露出来。

---

## 一、主线（审计的判据）

**主线**：这一页让你看清每个工具吃掉多少上下文，并逐个决定去留。

**反面**：它只是把工具列出来给你看，改不改与 token 无关。

如果反面成立，那么「字符 / tokens 统计」「节省」这些都不该出现；
如果正面成立，那么页面显示的**开关状态必须与引擎实际判定一致**——
否则它不是「让你决定去留」，是「让你看着一个假状态做决定」。

**不写什么**：工具的功能介绍、调用示例、服务器连接配置。
（这三样在页面里出现任何一处，都是越界。）

**给谁看 / 读完能做什么**：给已经装了几个 MCP 服务器、发现工具太多的人；
读完能判断关掉哪个，并把说明改短。

## 二、术语账本

审计中修订的用词，锁定后不再漂移。

| 定为 | 不许再叫 | 说明 |
|---|---|---|
| 受保护 | 基础工具 | 指 `PROTECTED_TOOLS` 里的工具；页面上曾用两个名字 |
| 原始说明 | 服务器原始说明 | 内置工具没有服务器，一律写「服务器」是事实错误 |
| 工具定义 | schema | 全页只有一个英文词 `schema`，且只出现一次，属于孤立术语 |
| 隐藏 / 启用 | drop / keep | 配置里用 `drop`/`keep`，界面用中文，不混用 |
| 刷新 | 重试 | 同一个动作（重新取数），两个名字；错误态说「重试」可接受，但不该复用「处理中」文案 |

**一名两义**：审计未发现需要拆名的词。

## 三、查出的累积矛盾

按严重程度排列。前四条会让人**依据错误信息做决定**，属于必修。

### 1. 页面显示的开关状态与引擎判定不一致（最严重）

页面只读配置里的 `rules.tools`（单工具规则）来画开关，**完全忽略服务器白名单
`serverKeep` 与总开关 `disabledServers`**。

而 `rules.js` 的 `decide()` 优先级是：
受保护 > 单工具 > **服务器白名单** > **服务器总开关** > 改写。

后果：配置里写 `servers: { tinyfish: { keep: ["search"] } }`，引擎会把
`fetch_content`、`create_dataset` 丢掉，但页面上这两个开关**显示为开**。

实测确认：

```
配置: tinyfish 只保留 search
工具名                        引擎判定   页面会显示
mcp__tinyfish__search         开        开
mcp__tinyfish__fetch_content  关        开   ← 不一致
mcp__tinyfish__create_dataset 关        开   ← 不一致
```

**修法**：API 的 `state` 直接用 `decide()` 算出每个工具的 `effective`
（`keep`/`drop`）与 `source`（`protected`/`tool`/`server`/`unknown`/`rewrite`/`none`），
页面只认 `effective`，不再自己推断。由服务器规则导致的关闭，行内注明「服务器规则关闭」。

### 2. 摘要与列表自相矛盾

搜索「tinyfish」后屏幕上只剩 2 行，摘要仍写「共 105 个工具」——
摘要算的是全量，列表画的是筛选结果。同一类信息在两处用两套口径。

**修法**：摘要描述屏幕上的工具（「筛选出 2 个工具 · ≈N tokens（全部 105 个）」），
隐藏计数与节省也按筛选后统计。

### 3. 内置工具的说明标签写错

展开内置工具（`read`/`pwsh`）时标签写「**服务器**原始说明」，
但内置工具没有服务器。这是事实错误。

**修法**：MCP 工具写「服务器原始说明」，内置工具写「原始说明」。

### 4. 「受保护」的说明被删掉了

页面某些行没有开关、只显示一个标签，但**没有任何地方解释为什么**。
上一版底部有一句说明，重构时被删了，读者只能猜。

**修法**：统一标「受保护」，并在底部注明「标「受保护」的工具任何配置都关不掉」。

### 5. 「刷新」按钮报告了别的操作的状态

`busy` 由开关、保存、恢复出厂共用，于是点一次开关，**刷新按钮的文案会变成
「处理中…」**。用户点的是开关，变的是刷新按钮。

**修法**：刷新按钮文案固定为「刷新」，只用禁用态表达忙碌。

### 6. 一句自相矛盾的话

「已保存到配置。重启 DSH 后对**新注册的工具**生效。」——
暗示只有部分工具生效，实际是重启后全部重新注册、全部生效。

**修法**：「已保存到配置。重启 DSH 后生效。」

## 四、一致性问题（已修）

- **孤立术语**：说明里的 `schema` 全页只出现一次，改成「工具定义」。
- **加载态文案与加载后不一致**：加载中显示短版说明，加载后换成长版，造成文字跳变。
- **类名漂移**：`.tw-itemT` 无意义，改为 `.tw-item`。
- **改写入参对象**：View 里往 `role` 上挂 `rewritten`/`currentRewrite`，
  是纯展示组件里的副作用；改成外部查表。

## 五、通读没修、但需要知道的缺口

这两项是**能力缺口**，不是 bug，改动超出「审计并修正」的范围，单列出来。

1. **参数级改写进不去**。`toolwarden` 模型工具和配置都支持
   改写参数说明（`rewrite.<tool>.properties`），但页面只编辑工具级 `description`。
   也就是说：页面自称管理入口，实际只覆盖了一半的改写能力。

2. **「恢复出厂」没有二次确认**。一次点击即清空全部规则。
   API 侧会留备份文件（`.bak-<时间戳>`），但页面上没有提示备份在哪，也没有撤销入口。
